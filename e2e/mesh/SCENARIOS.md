# 多节点集成场景

Mesh 套件检查跨机器连接、执行放置、计划、验证和数据边界。测试进程承担 Hub，两台执行节点由 [fleetlab](../fleetlab/README.md) 提供独立文件系统和进程环境。

## 运行环境

```sh
STEVE_MESH_E2E=1 go test -count=1 -timeout 25m ./e2e/mesh/
```

默认使用 Docker 节点。不可用时套件会报告跳过；需要前置条件缺失即失败的验收入口使用 `make e2e-fleet`。

真实模型场景增加 `STEVE_MESH_REAL=1`，并为 node-a、node-b 提供 `STEVE_LAB_NODE_A_ADDR`、`_TOKEN`、`_HOME` 等配置；HOME 必须是目标机器绝对路径。远端命令使用 SSH，节点控制默认 `~/steve-bin/nodectl`，可用 `STEVE_LAB_NODECTL` 指定。

真实节点需要预装已授权的 agent。使用专用测试节点，并确认它们允许由测试 Hub 调度；归属冲突应按[节点移交](../../docs/operations.md#在控制台添加机器)处理，不能靠重试绕过。

## 覆盖范围

| 场景 | 可观察结果 |
| --- | --- |
| 节点登记 | 机器、harness 和能力可见，缺失工具有具体原因 |
| 远程会话 | Agent 进程位于目标节点，回复返回协调端 |
| 反向 MCP | 工具请求经认证节点通道使用原会话权限 |
| 连接中断 | 执行和节点状态反映中断，恢复连接可被观测 |
| 能力放置 | 不满足 requires 的目标被拒绝并说明原因 |
| 计划并行 | 独立步骤确实重叠，依赖步骤等待前置结果 |
| 命令与 Agent 验证 | 验证在声明位置执行，失败约束完成状态 |
| 计划修订 | Findings 引发修订，已完成工作可被复用 |
| 数据等级 | 低等级节点不可接收高等级项目，sealed 保持主机范围 |
| 区域租约 | 资源由所属区域签发租约 |
| 内容直传 | 节点之间传输遵循协调端授权 |
| 读模型 | 任务、执行、能力和用量来自持久事实 |

真实模型用例检查各 harness 能否回答，以及模型规划、远端执行和委派的实际结果。具体断言以该目录测试为准；测试覆盖不表示任意节点故障都能无损自动恢复。
