# 能力包与插件模型

Steve 的能力包把 Skills、MCP 声明和 Agent 预设作为一个可安装、可固定版本、可分发到节点的单元；控制台「插件」页与管理 API 负责导入、审核、配置、启用、升级/回退和安全移除。操作步骤和清单字段见 [操作与作者指南](plugins-local.md)。往其他节点部署要求 hub 作为集群应用运行，独立 hub 只能导入、配置和管理本机。

## 事件 Provider 与能力包

邮件、日程和 IM 接入以外部服务运行，遵循独立的 [事件与客户端协议](event-providers.md)：使用受限连接凭据发布事件、消费已订阅的投递，并在显式授权的会话和项目中调用智能 Work。控制台统一管理订阅、处理回执和兜底 Inbox。它们不注入 harness 配置，也不获得 owner token。

原生 IM 集成可通过 `app.Config.Adapters` 注册具名 `channel.Provider`：它负责认证、规范化输入、接收原生动作和确认消息回执；Gateway 复用受理、恢复与投递逻辑，Work 复用现有 ACP 执行。最低实现是纯文本 Adapter，卡片渲染和线程能力另行声明。此入口是 Go 应用组合端口，默认命令不提供任意动态库加载。

用户主体以渠道与原生 ID 的组合解析。跨渠道绑定须 owner 显式操作；连接 token 不等同于用户。受控 Work 可投递到已授权的原生私聊或 Console，项目和真实 owner 锚点在受理时检查。结果不明的自动化原生发送会进入 Inbox，插件应使用稳定输入 key，重试沿用原 Work 回执并保留对账要求。账号与项目授权见 [服务边界](service-boundaries.md)。

事件 Provider 与能力包可以由同一作者提供，但生命周期和权限是两份独立契约。

能力包保持可信作者、显式安装的执行模型：包装成插件不会为 MCP/Skills 额外提供进程沙箱、网络限制或副作用代理，界面如实列出命令、外部服务和凭据用途。

## 一个包可以贡献多个扩展点

包是安装与升级单位，扩展点是核心调用它的契约。包内运行代码复用已有协议：工具通过 MCP，Agent 通过 ACP，技能与预设通过声明。运行代码使用受管理的外部进程或服务，不使用 Go 动态库、反射式注册框架或第三种 Agent 执行协议。

| 扩展点 | 支持 | 说明 |
|---|---|---|
| Skills | 包内技能及其资源 | 按授权范围装配 |
| MCP | 固定服务定义、安装来源、参数与配置需求 | 远程 MCP 只固定配置，不固定服务端实现 |
| Agent 预设 | 现有 harness、模型偏好、技能/MCP 组合 | 实例化后保留来源与用户覆盖 |
| Harness | 复用已有接入和可信安装目录 | 包不安装新的 harness |
| 验证器 | 复用现有验证行为 | 包不注册自定义验证器 |
| 触发器、事件处理 | 不由能力包注册 | 使用事件 Provider 契约 |
| 知识来源、能力探测 | 作为普通 MCP 工具使用 | — |
| 规划策略、报告展示 | 不开放自定义运行入口 | — |

## 包、配置与授权

包清单 schema 1 / `steve.plugins.v1`、本地准备回执、节点插件包准备协议与版本化凭据引用已实现，见 [本地契约](plugins-local.md)。`config.Plugins` 和共享配置保存期望安装；运行引用已进入 attempt、聊天会话和节点会话，插件运行时属于节点协议 v2 基线。

### 不可变包与可变安装

| 对象 | 必须表达的内容 |
|---|---|
| 包清单 | 作者命名空间下的稳定 ID、版本、清单 schema、Steve/节点兼容要求、能力声明、平台需求、配置项与所需权限 |
| 已解析包 | 完整源码提交或归档来源、规范化内容摘要、各能力入口、执行依赖的精确版本与可校验内容身份 |
| 安装配置 | 选择的包摘要、目标机器、启用范围、普通配置、节点凭据引用、配置修订号 |
| 节点回执 | 包摘要、配置修订号、实际准备状态、缺失依赖、失败原因、运行配置摘要 |
| 会话绑定 | 解析后的全部包与能力摘要、运行配置身份、MCP 定义版本、授权关联和持久引用 |

人可读的版本号不代替内容摘要。同一发布身份出现不同内容时拒绝覆盖并报告冲突；检查更新可以显示新版本，安装与会话解析使用固定身份。远程 MCP 的配置可以固定，其服务端实现可能独立变化，不能宣称远程服务代码也被固定或可离线重现。

来源为本地目录快照和固定 Git 提交：安装时读成不可变包，本地文件或分支后续变化不影响已装版本。没有插件市场、自动更新或插件之间的递归依赖求解。可执行依赖只支持能够锁定版本并核验来源的方式；未支持的安装方式明确拒绝。

### 配置权威与命名

协调配置保存期望安装与启用范围，遵循现有配置文件 CAS 与持久化规则；账本保存管理操作及受理/执行回执，节点保存本机内容、运行配置和安装事实。配置投影未完成时，受影响能力停止新的准入并显示待协调状态，不把部分完成报成成功。复用现有配置恢复模式，不要求配置文件、账本和远端磁盘跨存储原子提交。

包内能力具有稳定命名空间，例如逻辑身份由“包 ID + 能力种类 + 包内名称”组成；映射到各 harness 的文件名和 MCP 名称须确定且无碰撞。与内置能力、用户同名资源的冲突必须在预览阶段指出，不能依靠装配顺序覆盖。

Agent 预设在用户选定机器与本地 Agent ID 后实例化，保存来源摘要和用户覆盖。包升级只更新模板候选；更新已有 Agent 必须呈现具体配置差异并走原有保存路径。卸载不能删除用户手写或已转为用户管理的资源。

### 作用范围与凭据

以项目为使用范围、以节点为安装位置；Agent 预设本身不扩大项目权限。读取元数据、下载准备、配置凭据、启用到项目和实际执行是不同动作。安装完成不自动把工具暴露给所有 Agent，也不自动运行包内命令。

凭据声明只包含用途与配置需求；值留在执行节点或其 broker，协调元数据、包内容、同步包和日志中保存引用或脱敏状态。对远程 MCP，同样在执行节点解析连接凭据。包 ID 或包作者身份都不等于 owner 权限。

启用所需授权必须与包摘要和作用范围关联；升级增加能力、改变执行命令或凭据用途时，先展示差异再激活。权限被撤销后，旧版本绑定不恢复已经失效的授权；核心继续对它管理的调用检查执行身份和当前策略。已发出的外部请求不因停用而自动撤回。

包本身可能包含私有文档与业务逻辑，分发也遵守来源和数据等级约束；节点可联网或能执行某个二进制不代表它有权接收该包或项目内容。

## 多节点准备与激活

一次安装具有稳定管理命令 ID。相同 ID 和相同内容重试读取原操作，内容不同返回冲突。安装管理不虚构模型 attempt 或 token 消耗。

1. **预览**：解析清单和固定来源，展示能力、命令、配置需求、范围与变更；未知能力或不兼容 schema 直接拒绝。
2. **准备**：在获准机器上校验包内容、解析节点配置、准备依赖和独立运行目录。准备过程不向会话发布能力。
3. **记录回执**：节点持久记录包摘要、配置修订与实际状态；协调端核对回执身份，过期回执不能激活另一版配置。
4. **激活**：在配置与授权边界内发布完整的能力集合，再允许新会话解析。单个目标范围里的技能、MCP 与预设引用必须一致，不暴露半包。
5. **持续协调**：失败、离线和旧协议节点分别显示原因，可用同一操作重试。重启从记录恢复状态，不能把超时当成确定失败而盲目重复安装。

跨节点不承诺同时切换。期望版本统一，节点逐个准备并激活；新会话只能选择与期望摘要匹配、已准备且获准的节点。其他节点显示待同步/失败，不能静默用旧版启动新会话。已固定旧版的会话按下节保留。

包内容及部署记录应有与协调交接相匹配的恢复路径：内容进入获准的内容复制/保留机制，节点仍独立报告本机事实。共识只记录确定的描述与回执；下载、安装、进程启动和插件调用都在事务与 Raft 回放之外执行。相应管理动作沿用现有协调身份和栅栏，旧协调者的迟到请求不能激活新配置。

## 会话版本固定、升级与卸载

每个新会话解析一次已启用能力集合，得到运行配置身份。身份覆盖包摘要、技能内容、普通配置、凭据引用修订、MCP 定义和会影响启动的 harness 配置；授权关联另行检查，不能仅靠摘要授权。

物化目录和进程路由都必须使用该运行配置，不能只修改指纹。包目录不可原地替换，技能视图不指向可变源码；复用进程不得跨不兼容运行配置。需要共享同一个 ACP 进程的会话只能共享它实际支持的相同配置，hub 与节点两条启动路径遵循同一规则。

| 动作 | 新会话 | 已绑定的会话与待恢复执行 |
|---|---|---|
| 安装但未启用 | 不可选 | 无变化 |
| 激活新版 | 解析新版及其配置 | 继续使用原摘要、目录与服务定义 |
| 回退默认版本 | 经兼容与授权检查后解析选定旧版 | 各自保留原绑定，不回滚任务与外部副作用 |
| 停用 | 阻止新的会话绑定 | 显示仍在使用的会话；在现有授权下完成或由用户显式停止 |
| 移除内容 | 无入口 | 所有持久引用释放并确认没有相关进程后才回收 |

存活但空闲的会话仍是引用；失联节点、停止未确认或可恢复执行也不能按超时清零。卸载先停止新绑定，再展示阻塞项；不因卸载强杀 Agent。需要紧急撤权时走现有撤权/停止路径，并保留未确认的对账状态。

重启或协调交接后，从会话、待恢复执行与节点记录重建引用，不能只靠进程内引用计数。原版本丢失时明确进入待恢复状态，不用当前最新版替代，更不能为补装而重放已发送的 prompt。

## 核心职责与事件

`ledger`、`attempt`、`task`、`lifecycle`、`execution`、`artifact` 和 `coordination` 继续掌握事务提交、预算、租约、执行停止、恢复与落地。插件使用核心提供的窄接口，不能取得数据库事务或任意推进任务状态。内部生命周期函数的钩子也不直接公开为插件 API。

事件订阅在提交后运行：事件与提交事实关联，有稳定事件/投递身份与可恢复回执。重试按至少一次投递设计；外部目标不支持幂等时，对结果不明的调用提供对账，不能承诺恰好一次。

能力包不提供可阻断检查；已经发生的落地与对外操作不能被迟到的检查撤销。Steve 能观察和控制的是它承载的入口，不能把 harness 内部所有工具调用都算作已被统一拦截。

## 采用已有配置

已有 Skills/MCP 配置以 **Agent 的能力引用** 为粒度采用：用户逐项选择由包中哪项能力替换旧引用，同一次 Agent 配置 CAS 保存来源和剩余引用。旧资源目录及机器 MCP 定义仍属于用户，其他 Agent 可以继续使用；插件会话不会再复制已采用的同名全局技能。旧 Skills/MCP 页面列出插件能力来源并链接到安装管理，仍被其他 Agent 使用的源文件或服务定义不会被悄悄转移所有权。

预设更新保留用户修改；移除安装只解除对应 Agent 的预设来源，不删除 Agent，也不自动恢复已替换的旧引用。运行目录与原生会话只在引用释放、相关节点可核实且进程明确退出后清理。共享包库和安装命令历史保留，便于审计和重新安装。
