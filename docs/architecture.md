# Steve 架构

本文记录当前代码的职责、依赖与一致性边界。使用与配置见 [README](../README.md) 和 [运维指南](operations.md)。

`internal/architecture` 的棘轮只允许数字变好：超过 120 行的非测试函数、`cmd/steve` 的行数与内部依赖数、临时接口断言和内联字符串状态都以基线文件记录，出现新违例或基线残留已消失的条目都会失败；清理后用 `RATCHET_UPDATE=1` 重新生成基线。面向用户的中文字面量同样按声明记录在 `user_text` 基线中（现已清空），只减不增，新文案经 `i18n` 目录按读者语言输出；给 Agent 读的输入、识别用户输入的词表和按 locale 与英文并列选择的文本可以豁免，但豁免只能精确到一个函数、`类型.方法` 或包级常量/变量，并写明理由，不接受整文件、整目录或整批包级声明。经目录说出的错误由 `Catalog.Errorf` 生成，模板里的 `%w` 在每种语言中都包住原错误；含 `%w` 的模板不经 `Catalog.T` 读取，也不交给 `fmt.Errorf` 格式化。

对仓库内非空接口的类型断言或 type switch 分支（能力探测）在实现改名或签名变化后仍能编译，只会静默走回退分支。因此只有一个生产实现的被探测接口，要在一个能同时引用接口与实现的包里，用 `contracts_test.go` 中的包级 `var _ I = (*T)(nil)`、`T{}` 或 `pkg.T{}` 在编译期钉住实现，T 必须声明在非测试文件中，测试替身或 `nil` 不算钉住；断言放在测试文件里，不增加生产依赖。多个生产类型有意实现或不实现的接口，记入 `internal/architecture` 的 `openCapabilities` 并写明理由；条目对应的接口不再被探测时测试失败。既未钉住也未列入 `openCapabilities` 的被探测接口按接口记录在棘轮基线中，只减不增。`consoleapi.Admin`、`Console` 和 `PluginsService` 的每个方法，连同它们嵌入的 `consoleapi` 接口的方法，都必须在 `internal/httpapi` 中被调用或以方法值引用，否则测试失败。

依赖门禁禁止领域层反向引用应用/传输层，禁止契约包引用服务实现。传递依赖门禁要求 `config`、`i18n` 不链接执行层（exec、lifecycle、turn、node、harness）与存储层（ledger、SQLite），`consoleapi` 不链接执行层，`cmd/steve-node` 不链接 ledger 且只经 `node` 的会话记录使用 SQLite；违规时报告最短导入链。HTTP 实现只由组合入口装配，其他内部服务不导入它。包之间采用消费方所需的接口；运行期可替换的对象才需要接口。

`gateway` 仍包含飞书启动及主动投递逻辑；配置了飞书凭据才创建该适配器。独立 Console 使用 `gateway.owner_id`，无需建立飞书连接。`channel.Messenger` 统一 Agent 的进度消息操作；通道特有的卡片、设备授权和回调留在适配器内。

## 权威与提交点

### 复制回放与快照

应用复制请求以 `(ExpectedVersion, ID)` 标识，重试必须保留原身份与输入。共识状态按已提交应用版本推进回放下界，至少保留最近 4096 个应用版本，每 256 个版本推进一次。原请求早于下界时明确返回过期，调用者须核对业务事实，不能改用新版本自动重复原操作。这个窗口不限制单个版本上的拒绝请求数量；管理指令回执和审计也不按此窗口删除。

SQLite 物理回执只在本地共识快照成功持久化后清理。快照包含回放下界和完整保留后缀，捕获失败、写入失败或放弃快照都不删除在线回执；恢复之前捕获的清理回调不能作用于恢复后的实例。物理清理失败只延迟清理，不撤销已经持久化的快照。业务命令、外部发送结果和未决执行证据不属于这项清理范围。

### 任务树预算

`task.Store.Begin` 在一次持久更新中检查任务及祖先的预算，并向每个祖先计入一次执行。`FinishAs` 仅传播本次执行的耗时、工具次数与 token，不再次传播子树累计值。

因此，同一组已完成执行的费用与完成顺序无关；重复结束同一个执行会被拒绝。并发子任务的执行次数由共同祖先的预算限制。计划分支使用 `ReserveTurn` 原子扣额度，不创建虚假的对话 attempt。耗时是执行后累计的观测量，不等同于可以预知并严格预留的费用。

### 项目与工作区

项目主目录和声明的副本在同一节点上不得重复或嵌套。`project.Store` 在账本事务内检查更新后的完整集合；批量声明、复制目录变更和并发声明使用同一约束。HTTP 的预检查只用于及时反馈，不能替代这一权威校验。

路径比较基于规范化路径；符号链接、不同节点名称指向同一物理目录等部署别名仍需由部署者正确配置。

### 执行结果

`attempt.Complete` 把租约校验、结果名称的版本比较、Result/Usage 和 Bound 终态放在同一账本事务内。名字冲突、失效租约或存储失败不会只提交其中一部分。对话、委派和计划执行使用这一提交边界。

发布快照与提交执行结果是不同阶段。提交未成功时，不能据此报告成功或继续落地；候选工作区可保留以便核查。接管旧执行只释放其完整租约凭据，不按资源名称撤销新持有者的租约。

用量从执行提供方进入时携带“是否上报”事实。已上报零消耗与未上报分别记录；结束 attempt 是 Dashboard 的用量来源，任务与计划上的费用字段不能再累加一次。

Dashboard 的未上报 Token 点按 0 连线，保留未上报次数。Token 总量为输入加输出，缓存读取和写入单列；不同提供方对缓存是否包含于输入的定义不一致，因此缓存不再加入总量。Agent、实际模型、Harness、触发来源和项目分组使用同一份结束 attempt。

1d / 7d / 30d 按 Hub 日历时区、执行开始时间归入区间。每个根任务的耗时为其父子执行区间的并集长度，不把并发区间重复累加；平均值的分母是有可测时间的根任务数。暂停后再继续之间的空闲时间不计，执行中等待用户答复的时间仍计入。跨多个分组的同一根任务可以在各组分别出现，因此分组任务数不可相加。

TPM 根据每次执行的 I + O 总量和持续时间均匀估算：区间平均值除以整个区间分钟数，有执行期间平均值除以执行区间并集分钟数，峰值取各自然分钟的估算 Token 数。无有效执行时间的 Token 保留在总量中，并作为不可估算部分报告。该指标用于资源消耗比较，不表示模型逐 Token 生成速度。

规划模型与 Agent 验证也持有独立 attempt、隔离工作树和 endpoint slot，并经过准入、预算和用量结算。上层编排保留各自控制流，共享硬约束与结束提交点。

### 子任务结果交接

子任务完成与父任务收到结果是两条独立事实。结果留在任务记录上，发送前原子固定批次成员和交接键。重试只重放原批次；此后完成的子任务使用新的批次，不能借用旧队列回执被误标成已送达。

父任务暂停、失败或等待审查时保留未交接结果；恢复至可运行状态后再交接。用户以 `/cancel` 停止任务后任务被记为 held（带停止时间戳）：held 期间不交接，任务下一个回合组装 prompt 时把未交接的结果和被停止的子任务状态写在用户消息之前；prompt 与 agent settle 后才标记为已送达并解除 hold，未 settle 的回合不改变任何状态，下一回合重复同样内容。解除 hold 只对组装时看到的那个时间戳生效：之后再次停止会重新盖戳，在更早时间戳下组装的回合 settle 时不会解除新的 hold；被停止操作本身取消的那个回合即使 settle 也只标记已送达、不解除 hold。停止开始时即对该会话中该 Agent 持有的每个任务盖戳，因此 stop 期间收尾的子任务（包括在被停止的回合里刚派发、自行结束的子任务）总是看到父任务已 held；停止结束时，没有子任务需要交代的任务按本次盖的戳解除 hold，有的则重新盖戳。暂停期间被置为 paused 的子任务在 settle 时收口为 cancelled——委派不可恢复，父任务自行决定是否重新委派。已有持久回执先核对处理结果，父任务关闭不影响确认已完成的交接。父任务完成或取消后尚未接收的结果记录 `suppressed`，不称为已送达。每 5 秒检查到期的交接；明确失败按 5 秒至 5 分钟指数退避，执行中或暂停的父任务不会被周期检查唤醒。

Console 先以带稳定键的持久 Exchange 接收，交接保持 `queued`，父任务处理成功后才标记 `delivered`。自动续接记录原父任务 ID，普通队列和重启恢复都保留该绑定。入队后父任务被暂停时，准入拒绝另行持久化；恢复后可重新排入同一个 Exchange，保留完整子任务答案。已准入后的失败或取消不能自动重放。会话重置或项目切换也不能借交接创建另一条任务。离线项目迁移会重映射父任务 ID。

飞书通知与父任务处理并非同一提交点。发通知前持久记录可能发生的发送；缺少回执或进程中断时保持 `uncertain`，不自动重发。只有父任务处理返回后才确认交接；确认回调不持有发送锁，父回合可以继续交接其他结果。它不承诺外部聊天系统的恰好一次执行；结果不明时先核对原会话，也可由父任务通过 `steve_await` 读取已持久化的子任务结果。

看板从任务树派生未交接与待确认数量并向祖先汇总；主任务计数不再累加子任务。交接状态变化产生任务更新事件，但不修改执行耗时。资源页比较运行进程上报的版本；版本不同表示需要检查部署，不等同于协议不兼容。

### 停止与恢复

`execution.Registry` 以任务、实例和 attempt 关联运行作用域。父回合正常结束时，已派发的子任务继续运行；用户停止当前回合（`/cancel`）时，仍在运行的直接子任务各自连同子树被取消并等待收尾，父任务保持运行状态和执行 epoch；显式暂停或取消任务时，任务树在一次持久更新中撤销原执行 epoch，随后取消并等待对应执行收尾。结果提交及落地准入检查原 epoch，之后重新恢复任务不会重新授权旧结果。

写入者无法确认已停止时，attempt 持久隔离，目录和有限 endpoint 容量不能由替代执行接管。连接关闭、租约到期或 Host generation 改变均不构成物理退出证据。启动先分类旧执行，再应用项目声明和恢复工作；只有具有明确静止证据的未完成执行可自动回收。服务关闭先停止准入并有界等待执行清理，再关闭存储与传输。

计划步骤的完整输出、定义摘要与原执行身份和 Bound 一起提交。计划缓存写入失败后可从已提交输出重建，不再次调用模型。工作流检查点用于恢复调度位置，不能替代 attempt 的完成事实。

计划运行记录依次经过 `executing → landing → completed`。每个输出分支有稳定落地 ID；所有约定落地完成后任务才结束。已进入 `applying` 的落地按原目标目录和 WAL 恢复，配置不能把该目录重新分配。已经准入的文件应用可能在取消之后完成；取消阻止的是后续执行与新的落地准入，不能撤销已发生的外部写入。

### 管理配置

Agent 变更依次执行：构造并验证候选目录、持久化配置、发布不可变目录快照。普通读请求只访问完整快照，不暴露可被外部修改的 map 或 slice。

配置文件的原子替换是提交点。替换前失败表示未应用；替换后目录同步失败返回 `config.CommittedError`，表示新配置已应用但持久性未确认。调用者在后一种情况下保持与新文件一致的运行态，不能回滚成旧配置并假称未应用。

配置文件是项目、工作区和配置 ACL 的声明权威；账本保留执行、产物及运行状态。配置保存前检查读取时的文件指纹，检测到外部改动便拒绝覆盖。`configbuild.ProjectController` 校验完整声明后保存文件，再事务更新项目投影和已应用摘要。两个存储没有跨存储原子事务；投影未应用时，项目执行解析关闭，重试或启动从当前配置重建。

移除项目保留历史查询入口，不允许用历史声明启动新执行。配置 ACL 作为独立覆盖层参与声明摘要，显式拒绝优先；移除配置授权后才显露独立运行时授权或项目默认值。

工作区 clone 是独立管理操作，不虚构模型 attempt 或用量。它持有副本目录租约，并在执行中及结果不明时保留持久隔离。超时不会自动判为失败后重复 clone；原进程退出需要明确证据，操作入口见运维指南。

Console 策略设置以配置修订号作 CAS，响应分别返回期望值、当前生效值和重启要求。运行期派生的 harness HOME 环境保存在副本中，不写回声明配置。节点配置另用持久修订号作 CAS，修订号检查属于节点协议 v2 基线。

### Console 提交

客户端以 `(conversation, command_id)` 标识同一次提交。规范化原始请求的摘要、交换状态及回执一起持久化在 Exchange 中。相同身份且内容一致时重放已有交换；同身份不同内容返回 HTTP 409。

取消的带键交换保留墓碑，避免重试使任务复活。带键终态回执的保留与界面最近消息列表的裁剪分开；界面列表不是去重权威。平台续接键与客户端键分属命名空间。

前端先保存提交身份再发送。网络中断、5xx 或无法解析的回执表示结果尚未确认；重试复用同一身份，不自动生成另一份工作。页面切换不会丢失进行中的发送或停止状态。

客户端写入前确认 Hub 支持 `submission_keys`。缺少这一能力或无法完成检查时，保留读取能力并阻止 Console 写入。结果不明的请求在重试失败后仍保留原身份；某次重试未发出不能证明原请求未被接收。

语言、引用和输入一起冻结为提交内容；重试和重载对账不能改变其中任意一项。附带材料还要求 `material_refs` 能力，不能在旧 Hub 上静默丢弃附件后发送。

### 材料与用户答复

材料保存内容摘要、原始项目与来源版本。回复以原始 reply revision 固定，源码和 Diff 分别绑定执行的 base/result commit；浏览器当前绑定的项目不能覆盖历史来源。上传及快照读取均受大小、MIME、路径和数据等级约束。下载经过鉴权，不作为同源可执行页面展示。

批注属于不可变材料上的独立可变记录，使用版本 CAS 和幂等命令 ID；删除保留墓碑。加入会话、加入侧栏与批注共用同一个引用结构，文本行、精确引用和图片区域保留各自选择语义。模型收到实际附件内容；缺少相应 ACP 能力时明确拒绝。

用户审批和 Ask User 请求记录 owner、exchange、task、attempt、session、generation 和 tool call。回答通过专门接口恢复等待中的请求，不作为普通聊天输入发送。拒绝和取消不携带已选择选项；超时、取消、重启和会话终止产生明确终态，旧回调不能恢复新一代会话。待答复请求同时出现在原会话和待处理页。

### 语言与版本

UI 使用类型化中英文词条和显式日期/数字格式，语言选择独立于业务内容。HTTP 请求协商语言；Coordinator 的请求视图只替换文案目录，共享运行状态和互斥锁，不修改全局语言或翻译用户、模型及工具原文。

版本接口报告当前 Hub、节点构建、协议和特性，以及配置中的其他 Hub；配置列表不等于在线探测。`ReleaseProvider` 是发布信息的查询端口，发现和安装分离；默认没有公网发布源或自动安装器。

### 多 Hub 归属与迁移

每个 Hub 使用 state 目录内持久身份，每个项目保存 `HubID / Epoch / State / TransferID`。只有本 Hub 的 active 项目可以准入执行；released 项目保留历史，配置重载不能使它复活。node 实例也持久绑定单一 Hub，断线不会授权其他 Hub 认领。物理机器上多个隔离实例可以分别服务不同 Hub。

完整项目迁移使用离线 bundle，源和目标都获取实例维护锁。源端先校验执行与落地已停止，保存且同步 bundle，再事务冻结队列、计划和定时任务并记录 released；只有这之后才发布最终 bundle。目标先验证来源、摘要、数据等级和路径，物化内容并完成文件/目录同步，再事务导入事实为 importing，保存配置声明，最后激活 active。中断导入由同一 bundle 重试完成；未完成时启动拒绝调度该半成品。

导入对运行记录的 ID 和显式引用建立来源命名空间，避免与目标现有任务碰撞；原始消息正文、材料内容摘要和来源记录不改写。文件内容、Git 历史和工作树分开传递，不复制源 Git hooks 或凭据配置。旧模型进程和内存中的审批回调不可迁移；对应等待记录明确中断，任务从持久状态恢复到新会话。结果不明的外部动作保留人工对账状态。

此接口提供显式移交和人工恢复，不提供共识仲裁、跨 Hub 自动选主或仅依靠心跳的容灾。离线包摘要验证完整性，不证明源 Hub 已停止；操作员负责可信来源与退出证据。具体命令和恢复边界见[项目迁移指南](project-migration.md)。

### 定时触发

每次触发冻结通道、项目、执行人和原触发时间，使用稳定 Firing key。认领、发送和受理是不同阶段；只有受理回执落账后才推进执行次数与下次时间。Console 以持久 Exchange 去重；不支持稳定发送幂等键的外部通道在结果不明时等待人工确认或明确重试，不能自动假设未执行。项目绑定漂移会拒绝该次执行。

### 记忆写入

Markdown 是记忆事实权威。同一 scope 的文件锁串行化写入；带幂等键的 Remember 先持久化包含目标内容、原内容摘要和稳定回执的 WAL，再原子替换事实文件，保存回执并清除 WAL。Forget、Replace 和无键写入也先完成遗留事务。读取只观察当前事实，不触发恢复写入。

24 小时窗口内的同键请求返回首个回执，即使该事实后来已删除。TTL 只限制普通请求去重；遗留 WAL 的提交证据不能因 TTL 过期被忽略。外部编辑使文件既不匹配写前也不匹配写后内容，且没有提交回执时，恢复拒绝覆盖这些编辑。审计与索引不承担提交权威。

## 读取与未知状态

快照各项查询分别报告 SourceHealth，账本汇总健康之外还区分活动、项目、落地、事实、待处理和用量。某项读取失败时，其余成功数据仍可使用。

查询失败不能推导出空闲或零待办：开放任务可显示 `unknown`，Agent/Workspace 用 `activity_known` 表示活动信息是否完整；已知的运行与待处理事实仍保留。`PendingResolution` 仅观察待对账操作，读取快照不会触发恢复写入。

隔离 writer 保留资源占用，以单独的待处理记录显示。没有其他已知执行时，其任务执行状态为未知，处理需求向父任务汇总；界面不提供绕过物理核实的一键解除操作。

## 前端边界

- `pages` 组合页面状态与交互；组件和数据模块不反向导入页面。
- `lib/api/*` 按业务领域提供 API；`lib/http` 负责传输与错误分类；普通请求使用 Authorization，EventSource 单独携带查询参数凭据。
- `lib/format`、执行过程投影和草稿解析是可独立测试的纯逻辑。
- 单资源读取同一时刻最多有一个在途请求；期间的刷新合并为后续一次读取，资源切换或卸载使旧结果失效。转写的事件版本仲裁另行保留。
- 配置编辑先保留原始草稿，提交时解析和校验；未完成的输入不是可丢弃的无效配置。多行环境变量和请求头使用显式 JSON 形式，argv 保留空值、空白与重复参数。
- 展示模块之间保持有向无环依赖。只读代码工作区与用量图表按需加载。

## 验证

`make test` 运行 Go 包测试与竞态检查，包含领域/传输依赖门禁。`make test-console` 运行前端依赖门禁、纯逻辑、生产构建与隔离浏览器交互测试。

并发测试使用事件屏障验证重叠与顺序；事务测试通过实际临时账本和故障注入验证回滚与提交点。CI 同时执行 Go 和前端测试。真实机群门禁仍是独立的合并要求，见 [CONTRIBUTING.md](../CONTRIBUTING.md)。
