# Steve 架构

本文记录当前代码的职责、依赖与一致性边界。使用与配置见 [README](../README.md) 和 [运维指南](operations.md)。

## 模块与依赖

| 模块 | 职责 | 主要依赖 |
|---|---|---|
| `cmd/steve` | 进程启动、组件装配、管理用例适配 | 应用服务、配置、HTTP 与通道适配器 |
| `httpapi` | HTTP 鉴权、请求解析、响应与事件流 | `consoleapi` 契约、只读模型接口 |
| `consoleapi` | Console/Admin 端口、交换与回复等序列化结构 | 领域值类型；不执行网络或存储操作 |
| `console` | 会话交换队列、提交去重、回复记录 | 协调入口、账本文档、事件端口 |
| `readmodel` | 系统快照、派生状态、用量与事件聚合 | 各领域的查询接口、`consoleapi` 数据结构 |
| `turn`、`delegate`、`exec` | 对话回合、委派与计划的业务编排 | task、attempt、artifact、project、harness 等领域服务 |
| `execution`、`agentexec` | 执行作用域、停止等待，以及规划/验证的单次执行壳 | task、attempt、harness 与资源准入端口 |
| `schedule` | 定时规则、触发认领与受理回执 | 持久化文档；通道投递由组合入口装配 |
| `task`、`project`、`attempt` | 任务树预算、工作区归属、执行状态与租约 | ledger；不依赖 HTTP 或页面实现 |
| `ledger` | 文档、事务、命名引用、租约与审计 | SQLite 与本地持久化 |
| `artifact` | 快照、内容搬运、合并与落地 | 项目、账本、节点操作端口 |
| `node`、`nodewire`、`acphost` | 节点连接、可续接进程流、ACP 会话 | 协议、进程与资源接口 |
| `channel`、`channel/feishu`、`gateway`、`card` | 消息通道、飞书投递及卡片 | 协调入口与呈现数据 |

依赖门禁禁止领域层反向引用应用/传输层，禁止契约包引用服务实现。HTTP 实现只由组合入口装配，其他内部服务不导入它。包之间采用消费方所需的接口；运行期可替换的对象才需要接口。

`gateway` 仍包含飞书启动、调度及部分主动投递逻辑，当前启动仍需要飞书配置。`channel.Messenger` 已统一 Agent 的进度消息操作；这并不表示所有主动投递路径都已完全通道中立。

## 权威与提交点

### 任务树预算

`task.Store.Begin` 在一次持久更新中检查任务及祖先的预算，并向每个祖先计入一次执行。`FinishAs` 仅传播本次执行的耗时、工具次数与 token，不再次传播子树累计值。

因此，同一组已完成执行的费用与完成顺序无关；重复结束同一个执行会被拒绝。并发子任务的执行次数由共同祖先的预算限制。计划分支使用 `ReserveTurn` 原子扣额度，不创建虚假的对话 attempt。耗时是执行后累计的观测量，不等同于可以预知并严格预留的费用。

### 项目与工作区

项目主目录和声明的副本在同一节点上不得重复或嵌套。`project.Store` 在账本事务内检查更新后的完整集合；批量声明、复制目录变更和并发声明使用同一约束。HTTP 的预检查只用于及时反馈，不能替代这一权威校验。

路径比较基于规范化路径；符号链接、不同节点名称指向同一物理目录等部署别名仍需由部署者正确配置。

### 执行结果

`attempt.Complete` 把租约校验、结果名称的版本比较、Result/Usage 和 Bound 终态放在同一账本事务内。名字冲突、失效租约或存储失败不会只提交其中一部分。对话、委派和计划执行使用这一提交边界。

发布快照与提交执行结果是不同阶段。提交未成功时，不能据此报告成功或继续落地；候选工作区可保留以便核查。接管旧执行只释放其完整租约凭据，不按资源名称撤销新持有者的租约。

用量从执行提供方进入时携带“是否上报”事实。已上报零消耗与未上报分别记录；结束 attempt 是 Dashboard 的用量来源，任务与计划上的费用字段不能再累加一次。

规划模型与 Agent 验证也持有独立 attempt、隔离工作树和 endpoint slot，并经过准入、预算和用量结算。上层编排保留各自控制流，共享硬约束与结束提交点。

### 停止与恢复

`execution.Registry` 以任务、实例和 attempt 关联运行作用域。父回合正常结束时，已派发的子任务继续运行；显式暂停或取消任务时，任务树在一次持久更新中撤销原执行 epoch，随后取消并等待对应执行收尾。结果提交及落地准入检查原 epoch，之后重新恢复任务不会重新授权旧结果。

写入者无法确认已停止时，attempt 持久隔离，目录和有限 endpoint 容量不能由替代执行接管。连接关闭、租约到期或 Host generation 改变均不构成物理退出证据。启动先分类旧执行，再应用项目声明和恢复工作；只有具有明确静止证据的未完成执行可自动回收。服务关闭先停止准入并有界等待执行清理，再关闭存储与传输。

计划步骤的完整输出、定义摘要与原执行身份和 Bound 一起提交。计划缓存写入失败后可从已提交输出重建，不再次调用模型。工作流检查点用于恢复调度位置，不能替代 attempt 的完成事实。

计划运行记录依次经过 `executing → landing → completed`。每个输出分支有稳定落地 ID；所有约定落地完成后任务才结束。已进入 `applying` 的落地按原目标目录和 WAL 恢复，配置不能把该目录重新分配。已经准入的文件应用可能在取消之后完成；取消阻止的是后续执行与新的落地准入，不能撤销已发生的外部写入。

### 管理配置

Agent 变更依次执行：构造并验证候选目录、持久化配置、发布不可变目录快照。普通读请求只访问完整快照，不暴露可被外部修改的 map 或 slice。

配置文件的原子替换是提交点。替换前失败表示未应用；替换后目录同步失败返回 `config.CommittedError`，表示新配置已应用但持久性未确认。调用者在后一种情况下保持与新文件一致的运行态，不能回滚成旧配置并假称未应用。

配置文件是项目、工作区和配置 ACL 的声明权威；账本保留执行、产物及运行状态。配置保存前检查读取时的文件指纹，检测到外部改动便拒绝覆盖。`ProjectController` 校验完整声明后保存文件，再事务更新项目投影和已应用摘要。两个存储没有跨存储原子事务；投影未应用时，项目执行解析关闭，重试或启动从当前配置重建。

移除项目保留历史查询入口，不允许用历史声明启动新执行。配置 ACL 作为独立覆盖层参与声明摘要，显式拒绝优先；移除配置授权后才显露独立运行时授权或项目默认值。

工作区 clone 是独立管理操作，不虚构模型 attempt 或用量。它持有副本目录租约，并在执行中及结果不明时保留持久隔离。超时不会自动判为失败后重复 clone；原进程退出需要明确证据，操作入口见运维指南。

### Console 提交

客户端以 `(conversation, command_id)` 标识同一次提交。规范化原始请求的摘要、交换状态及回执一起持久化在 Exchange 中。相同身份且内容一致时重放已有交换；同身份不同内容返回 HTTP 409。

取消的带键交换保留墓碑，避免重试使任务复活。带键终态回执的保留与界面最近消息列表的裁剪分开；界面列表不是去重权威。平台续接键与客户端键分属命名空间。

前端先保存提交身份再发送。网络中断、5xx 或无法解析的回执表示结果尚未确认；重试复用同一身份，不自动生成另一份工作。页面切换不会丢失进行中的发送或停止状态。

客户端写入前确认 Hub 支持 `submission_keys`。缺少这一能力或无法完成检查时，保留读取能力并阻止 Console 写入。结果不明的请求在重试失败后仍保留原身份；某次重试未发出不能证明原请求未被接收。

### 定时触发

每次触发冻结通道、项目、执行人和原触发时间，使用稳定 Firing key。认领、发送和受理是不同阶段；只有受理回执落账后才推进执行次数与下次时间。Console 以持久 Exchange 去重；不支持稳定发送幂等键的外部通道在结果不明时等待人工确认或明确重试，不能自动假设未执行。项目绑定漂移会拒绝该次执行。

### 记忆写入

Markdown 是记忆事实权威。同一 scope 的文件锁串行化写入；带幂等键的 Remember 先持久化包含目标内容、原内容摘要和稳定回执的 WAL，再原子替换事实文件，保存回执并清除 WAL。Forget、Replace 和无键写入也先完成遗留事务。读取只观察当前事实，不触发恢复写入。

24 小时窗口内的同键请求返回首个回执，即使该事实后来已删除。TTL 只限制普通请求去重；遗留 WAL 的提交证据不能因 TTL 过期被忽略。外部编辑使文件既不匹配写前也不匹配写后内容，且没有提交回执时，恢复拒绝覆盖这些编辑。审计与索引不承担提交权威。

## 读取与未知状态

快照各项查询分别报告 SourceHealth，账本汇总健康之外还区分活动、项目、落地、事实、待处理和用量。某项读取失败时，其余成功数据仍可使用。

查询失败不能推导出空闲或零待办：开放任务可显示 `unknown`，Agent/Workspace 用 `activity_known` 表示活动信息是否完整；已知的运行与待处理事实仍保留。`PendingResolution` 仅观察待对账操作，读取快照不会触发恢复写入。

隔离 writer 保留资源占用，以单独的待处理记录显示。没有其他已知执行时，其任务执行状态为未知，处理需求向父任务汇总；界面不提供绕过物理核实的一键解除操作。

## 前端边界

- `pages` 组合页面状态与交互；组件和数据模块不反向导入页面。
- `lib/api/*` 按业务领域提供 API；`lib/http` 负责传输与错误分类；普通请求使用 Authorization，EventSource 单独携带查询参数凭据。
- `lib/format`、执行过程投影和草稿解析是可独立测试的纯逻辑。
- 单资源读取同一时刻最多有一个在途请求；期间的刷新合并为后续一次读取，资源切换或卸载使旧结果失效。转写的事件版本仲裁另行保留。
- 配置编辑先保留原始草稿，提交时解析和校验；未完成的输入不是可丢弃的无效配置。多行环境变量和请求头使用显式 JSON 形式，argv 保留空值、空白与重复参数。
- 展示模块之间保持有向无环依赖。只读代码工作区与用量图表按需加载。

## 验证

`make test` 运行 Go 包测试与竞态检查，包含领域/传输依赖门禁。`make test-console` 运行前端依赖门禁、纯逻辑、生产构建与隔离浏览器交互测试。

并发测试使用事件屏障验证重叠与顺序；事务测试通过实际临时账本和故障注入验证回滚与提交点。CI 同时执行 Go 和前端测试。真实机群门禁仍是独立的合并要求，见 [CONTRIBUTING.md](../CONTRIBUTING.md)。
