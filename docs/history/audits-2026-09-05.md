## 四、架构 refresh 评审（对 docs/architecture.md 初稿）

结论：方向可取，但接口与实施依赖尚不足以支撑终态。以下路径省略 `internal/`。

1. **事实与承诺需修正。** §7“task JSON 文件迁入 ledger”已过时：生产入口已调用 `task.OpenLedger`（`cmd/steve/main.go:617`）；真正欠缺的是跨对象事务，`ledger/document.go:51` 仍独立提交。§4.3 的 `steve_recall` 与现有记忆查询重名（`agentmcp/memory.go:144`）。§3“先落地再说话”也不准确：排队或冲突仍会投递结果（`delegate/deliver.go:179、205、215`）。§6“一二进制一配置”与保留 Git、Node 前置条件自相矛盾，应明确豁免。

2. **分层表不能按现包直接成立。** `go list -mod=readonly` 确认：记录层 `attempt→ability`、`project→nodewire`；执行层 `node/nodewire→ability`、`agentmcp→memory`，均违反表列方向。`ability` 更适合基础契约层；`attempt` 含生命周期协调，`artifact` 含远程执行与落地，不能整体称“纯本地记录”。`readmodel→node/artifact/task` 也非仅依赖观察接口，且承载写入口（`readmodel/server_taskmeta.go:32`）。须拆查询投影与命令服务，并补齐 `conversation、permission、capability` 的归属。

3. **§4 接口缺少可验证的语义。** `Post` 无明确操作幂等键、持久回执与“不确定是否送达”状态；入站回调无确认/拒绝协议。消息需稳定 ID、exchange/task/attempt 关联、顺序及版本。`Can()` 应按目标/消息查询编辑期限；过期追加须返回替代映射，撤回失败不能假成功——现控制台撤回正是空操作（`console/sender.go:42`）。权限往返须绑定 requestID、主体、会话、attempt、选项、期限及一次性消费，普通 yes/no 无法消歧；控制台尚未传询问回调（`console/console.go:588`）。单个 Anchor 不能表示多通道绑定：应分离会话与端点绑定，规定回复原通道、广播范围、审批归属及逐端点回执。审计原文第27—35行已有目标能力、Receipt、鉴权与单写要求，refresh 将其弱化了。

4. **§7 最大风险是把计划执行降为委派语法糖。** `exec` 已承担 DAG、重试、校验、检查点恢复（`exec/compile.go:196、327、725；exec/resume.go:108`）；双工投递不能替代这些语义。且 `delegate` 今天反向使用 `exec.ReportingContract/ParseRefs`（`delegate/delegate.go:585、607`）。替代：先抽共享 attempt 执行服务，保留计划调度器，两种协调方式共用执行；完成恢复等价验证后再收敛。

5. **§9 依赖漏边且分工冲突。** A1 的纯控制台快速开始应依赖 B3；目前仍强制验证飞书配置（`cmd/steve/main.go:1091`）。B3 应等待 B1 的通道契约冻结，仅依赖 A4 不够。A2/A3 都会改 `node` 配置、能力申报；A4/B1/B3/B2 汇聚 `cmd/steve` 装配与路由，B1/B2 又争用 `gateway` 权限逻辑。C1 的 task 事务改造会碰 A4 的持久化路径，且不应与执行器重构捆绑。C2 全仓文案迁移应排在相关包接口稳定之后。

6. **终态必须补写**：对象基数与唯一权威、任务/attempt/投递的事务边界；断线、hub/node 重启分别如何恢复；租约围栏、取消与预算传播；身份映射、会话 ACL 和审批授权；outbox 重放、未知副作用处置；节点协议兼容及迁移回退时的单写规则。仅列“持久化”“独立 token”不足以证明崩溃不丢任务、跨会话不可越权。
