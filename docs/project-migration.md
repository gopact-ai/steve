# 项目迁移

离线迁移用于把完整项目从一个独立 Steve 实例移交给另一个实例。它保留项目内容和历史，目标建立自己的运行身份。集群内协调交接使用[桌面指南](desktop.md#协调与交接)，无需导出项目。

## 迁移条件

源与目标有稳定 Hub ID，可在控制台查看。显示主机名不能替代 ID。两个 Hub 都需停服，并确认项目的本机和远端执行进程已退出、落地和复制结果已对账；维护锁不证明远端进程停止。

目标准备可用的 agent、harness、认证和数据权限。项目主目录使用新的本地空目录，不与目标已有项目或副本重叠。目标数据等级必须覆盖项目，路径按真实目录检查。

## 导出和导入

在源机器运行，替换实际路径、项目与 Hub ID：

```sh
steve migrate export --config /srv/hub-a/config.json \
  --project work --target-hub hub-b \
  --evidence "已核实所有执行停止且落地完成对账" \
  --out /srv/transfers/work.bundle.json
```

主目录在远端节点时，增加 `--workspace-snapshot /srv/offline/work`，指向停服后完整复制的工作区，包括未提交、忽略文件及 Git 历史。源码压缩包或仅有提交内容不能替代；该选项不绕过 sealed 数据限制。

成功导出后源项目处于 released，不再执行。将 bundle 按项目数据等级传送至目标机器，再运行：

```sh
steve migrate import --config /srv/hub-b/config.json \
  --expected-source hub-a --in /srv/transfers/work.bundle.json \
  --home /srv/projects/work
```

导入核对来源、目标及内容摘要，写入状态和配置后报告 active。启动目标并检查项目、会话、历史、材料与待处理。目标不接管旧 ACP 进程；源实例可以继续服务其他项目。

## 保留的内容

迁移包含项目声明与授权、会话和回执、任务与执行、计划和定时工作、产物、审计、材料、批注、项目记忆，以及工作区文件和 Git 历史。嵌套仓库分别保留历史；目标重建 Git 元数据，不复制 hooks、认证或外部 worktree 指针。

运行身份及显式引用映射到来源命名空间，消息正文保持原样。源节点副本在目标隔离，需要重新声明。原模型审批与仅存内存的回调变为 interrupted；外部结果不明的动作继续等待对账。

连接凭据与 Provider 授权不随项目迁移。单文件上限 64 MiB，单次文件树复制上限 512 MiB。导入不合并目标已有同名项目，也不自动合并迁回原 Hub 后的多代历史。

## 中断恢复

| 状态 | 处理 |
| --- | --- |
| release 前导出失败 | 源仍有归属，修复原因后重试 |
| 已 released，最终 bundle 发布失败 | 保留错误指明的 `.partial-<transferID>`，核实原包后导入，不重新生成另一代内容 |
| 目标写入中断 | 保留原 bundle，以相同参数恢复；配置未完成时不能绕过导入直接运行 |
| 源机器故障 | 使用可信完整离线包或恢复状态，核实旧写入者不能继续后显式移交 |

保留源备份与迁移包直到目标核对完成。不要把旧备份另启为可写实例，也不要重新添加 released 项目来绕过归属。
