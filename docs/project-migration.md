# 项目迁移与人工恢复

Steve 允许多个独立 Hub 管理不同项目。每个 node 实例只归属一个 Hub；同一机器可运行多个端口、状态目录和 harness 环境互相隔离的实例。节点归属命令见[运维指南](operations.md#在控制台添加机器)，状态边界见[架构文档](architecture.md#多-hub-归属与迁移)。

当前使用 Unix 本机离线命令迁移完整项目。命令不会经网络调度其他 Hub，不会自动升级节点，也不提供自动选主或无仲裁的心跳接管。

## 准备

在源和目标的控制台配置页记录稳定 Hub ID。它来自 `gateway.hub_id` 或首次启动后持久化的身份文件；显示主机名不是该身份。

停止源项目的执行，确认本机及远端 harness 进程已退出，完成未确认的落地和 clone 对账。随后正常关闭两个 Hub。迁移命令会获取维护锁，拒绝仍运行的 Hub；锁本身不能证明远端进程已退出。

目标预先配置可用的 agent、harness、认证和数据等级。导入的项目主目录是目标 Hub 的本地目录，不能与目标已有项目或副本重叠；符号链接祖先按真实目录检查。项目的数据等级不得高于目标 Hub。使用一个新的空目录，不覆盖已有工作树。

## 导出和导入

在源 Hub 所在机器执行，替换所有路径和 ID：

```bash
./steve migrate export --config /srv/hub-a/config.json \
  --project work --target-hub hub-b \
  --evidence "已核实该项目所有执行进程停止且落地已对账" \
  --out /srv/transfers/work.bundle.json
```

源主目录位于远端 node 时，还必须提供 `--workspace-snapshot /srv/offline/work`，指向停服后完整复制到本机的目录。该目录必须包含当前文件、未提交及被忽略文件和 Git 历史；普通源码压缩包或仅提交内容不能代替完整副本。封闭数据项目不能用此选项绕过数据边界。

导出成功后源项目处于 released 状态，不再执行。bundle 含项目内容和历史，按项目的数据等级传送和保管；SHA-256 摘要用于验证完整性，来源可信性由操作员保证。

把 bundle 放到目标机器，执行：

```bash
./steve migrate import --config /srv/hub-b/config.json \
  --expected-source hub-a --in /srv/transfers/work.bundle.json \
  --home /srv/projects/work
```

目标命令验证来源和目标 ID，保存完整项目状态并写入配置，成功后报告 active。随后启动 Hub，在项目页、会话、历史、资料和待处理页核对。目标不继续使用旧 ACP 进程，会从持久状态建立新模型会话。源 Hub 可继续服务其他项目；不要通过重新添加相同配置来恢复已 released 项目的写权限。

## 内容范围

迁移包含项目声明和 ACL、会话与提交回执、任务与执行记录、计划及定时任务、产物和审计、材料与批注、项目记忆，以及当前工作区内容和 Git 历史。嵌套 Git 仓库分别保留历史；目标重建 Git 元数据，不复制源 Git 配置、hooks、认证和外部工作树指针。

运行记录和显式引用重新映射为来源命名空间，保留原始消息正文及材料来源。源节点副本在目标隔离，需在目标配置中重新建立可用工作区。待答复的模型审批、Ask User 和只在内存中保存正文的披露请求转为 interrupted；它们不能凭历史记录恢复旧回调。结果不明的外部动作继续等待人工对账，不能自动重复执行。

传输当前有独立内存/体积限制：单文件 64 MiB、单次文件树复制 512 MiB，超限明确失败。它不是大规模对象存储迁移工具。导入不合并目标已有的同名项目，也不支持把项目迁回保留旧一代事实的 Hub 后自动合并多代历史。

## 中断与人工恢复

- 导出在 release 前失败：源仍保有归属，处理失败原因后重试。不要同时启动替代 Hub。
- 源已 released 但最终 bundle 发布失败：错误包含路径，保留原始 `.partial-<transferID>` 文件；它记录的是已释放的那一代事实，不要重新导出一份不同内容。核实完整原包后用它导入。
- 目标在内容、事实或配置保存阶段中断：保留原 bundle，修复存储问题后使用相同参数重跑。不同 payload 不会覆盖未完成导入。配置未完成时启动会明确拒绝，不能跳过导入恢复直接开始执行。
- 源机器故障：只能使用可信的完整离线包或恢复的持久状态；先核实旧写入进程确实无法继续，再显式移交。只有心跳超时、没有源状态或仲裁服务时，不能安全自动接管。

保留源状态备份和迁移包直至目标核对结束。不要把旧 Hub 备份直接作为另一个可写 Hub 启动，否则会绕开归属约束。
