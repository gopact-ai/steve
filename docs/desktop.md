# 桌面 App 与多机协作

## 启动

macOS 13 或更新版本可从源码构建桌面 App。构建机需要 Go 1.27+、Git、Node.js/npm 和 Xcode Command Line Tools；建议再装一个 upx（`brew install upx`），用于压缩随 App 分发的 Linux 节点程序：

```bash
make desktop
```

节点程序通过 SSH 原样上传到目标机器，慢链路上一个包要传几分钟。打包时 Linux 版本会用 upx 压缩，约 73 MiB 降到约 33 MiB，代价是每次启动多几百毫秒解压；macOS 版本保持原样，因为 upx 不支持 Mach-O，压过之后签名也会失效。没装 upx 时构建会提示并照常继续，`STEVE_DESKTOP_SKIP_UPX=1` 可以在本地反复构建时跳过压缩。

构建脚本输出 `Steve.app` 的路径。也可指定新的输出目录：

```bash
./scripts/build-desktop.sh /tmp/steve-app
open /tmp/steve-app/Steve.app
```

原生窗口的导航恢复与 HTML 隔离预览检查可在 macOS 上运行 `make test-desktop`（需要 Python 3）；检查使用临时 loopback 测试页面和独立 WebView，不连接现有服务或提交任务。

首次启动会创建本机身份、私人工作目录和后台服务，本机成为协调节点。无需先配置其他机器或飞书。App 可以在没有 Agent 时打开；选择本机已经安装的工具进行登记后，即可执行任务。登记前需要在对应工具中完成登录。检测不会导入工具的登录凭据或聊天历史。

从 Finder 启动时，App 会补查常见用户安装目录，包括 Kimi 的 `~/.kimi-code/bin` 和 NVM 的 `~/.nvm/versions/node/*/bin`；不会执行 shell 启动脚本。已有绝对 PATH 目录优先，未指定 NVM 版本时按已安装的数字版本从新到旧查找。检测、适配器安装与 Agent 子进程使用同一套搜索路径。

关闭窗口不会停止后台服务。重新打开 App 会连接已有服务，保留本机身份、会话和入口地址。

替换 App 之后重新打开，启动器会比对正在应答的服务版本和这次启动的 App 版本。不一致时向服务登记一次「空闲后重启」，由服务自己在空闲时原地重新执行新二进制，PID 和入口地址都不变。服务当时就是空闲的，窗口最多等 12 秒即可用上新版本；正有会话在跑，窗口照常打开、任务继续跑完，重启排队到它结束之后自动完成。同一次服务和同一个目标版本只登记一次，反复开关 App 不会排出多次重启；等待期间再换一版 App，新的登记会接管旧的等待。登记失败只记录在启动结果里，不阻止 App 打开。设置页的「节点与服务」可以看到等待原因，也可以撤销或改为立即重启；立即重启会中断正在进行的会话，需要靠会话恢复接续。

页面加载期间显示等待状态；前端未能渲染或页面进程意外退出时，主窗口提供“重试”。重试只重新打开工作台，不会重新提交任务。构建产物包含 Finder 和 Dock 使用的应用图标。

对话输入草稿、已加入的引用和待确认提交会保存在本机；完全退出 App 后，重新打开同一 App 仍可恢复。它们不随协调节点同步，也不等于已经发送。多个窗口同时修改同一草稿时，界面会保留当前输入并要求选择版本。若提示草稿无法保存，请先复制重要内容，不要依赖退出后恢复。

Steve 平台能力位于 MCP 页的内置服务器 `steve`，使用说明通过 `steve_help` 查询。技能页不会提供同名的内置 skill。更新后会移除旧的内置技能及其运行环境链接；已打开的 Agent 会话可能仍缓存旧说明，需要新建会话后才使用当前上下文。

## 外观与阅读

HTML 文件在独立的 sandbox iframe 中预览，保留文件自身的样式和脚本交互，不与工作台共享 DOM 或存储权限；SVG 预览不执行脚本。预览框占满整个阅读区并作为页面自身的视口：页面在框内滚动，sticky 顶栏、100vh 版面和目录高亮按页面原有布局生效。桌面预览不能调用原生目录／文件选择器、替换工作台页面或打开外部窗口。依赖其他本地文件、登录状态或这些受限能力的 HTML 不等同于完整网站托管，可切换到“源码”查看。

在「设置 → 外观」调整显示模式、配色和字体；右上角主题菜单提供同一份配置的快捷入口。显示模式为跟随系统、浅色或深色；浅色与深色各自记住一个配色。设置页选择配色不改变显示模式，右上角直接选择某套配色则切换到其对应模式。

界面、阅读正文、代码各自设置字体与字号；标题独立设置字体和大小档位，并保留标题层级。时间、状态等辅助信息跟随界面字号派生。字体可使用预设或填写已安装的字体名称；不会下载字体，未安装时由浏览器使用后备字体。

可以从当前配色复制自定义皮肤，编辑基础颜色并在局部预览中检查，保存后才应用；内置皮肤不会被覆盖。配色支持 JSON 导入／导出，最多保存 32 套，单次导入最多 64 KiB。导入只读取版本为 `1` 的配色对象（名称、`light` / `dark` 模式与六位 HEX 基础颜色），不执行脚本、CSS 或外部资源。导入后先进入草稿，确认保存后加入列表。低对比度提示只测量所列的基础文字与背景颜色，不代表所有控件和状态都通过无障碍检查。

外观即时生效，无需重启服务，保存在当前 App／浏览器的本地存储中；同一来源的窗口同步更新，不随集群或其他浏览器同步。刷新及重新打开后保留；清理网站数据会清除这些偏好，请导出重要的自定义配色。若本地存储或浏览器跨窗口协调不可用，会提示无法持久保存：字体、模式等即时偏好仍在当前窗口生效；自定义配色保存失败则不应用，只保留编辑草稿。两者都不能依赖刷新后恢复。外观不修改项目、会话或服务端配置。

## 接入机器

在资源页选择“通过 SSH 接入”。机器列表来自本机 SSH config；选择机器并点击检查后，才会建立 SSH 连接。安装前会列出程序、目录、网络地址和成员变更。只有确认计划后才安装。

如果发现已有配置，界面会列出检测到的路径；环境允许读取记录时，还会显示配置中的节点名称和所属工作台。这些记录不代表服务正在运行。此时不会显示新安装表单，也不会覆盖原有身份或任务。可重新检查、查看本工作台的机器列表，或打开本机保留的接入记录。未知安装暂不支持在此直接导入或合并。

完整节点接入会说明其保存的协作数据范围。此前只选择较低数据范围的草稿，需要明确允许保存协作数据后才能继续审阅。只想运行项目任务的机器，可选择“仅作为执行节点接入”，按手动登记说明在远端安装并启动服务。

完整节点保存协作账本，包括任务正文、问答与私人记忆。因此完整节点的数据等级必须是 `restricted` 或更高；不能用“禁止自动接任”代替数据授权。只获准处理较低等级数据的机器，应通过手动添加入口接为执行节点，它不会成为账本副本或投票成员。

共享账本模式不支持 `sealed` 项目。`sealed` 的正文只能留在指定主机，不能进入整库复制；此类项目需要独立单机部署。独立部署命令见 [运维指南](operations.md)。

通过 SSH 接入的机器，其协作和选举协议走同一条 SSH 会话：本机以 `ssh <别名> 'steve link …'` 在该机器上运行刚安装的节点程序，两端在这条会话的标准输入输出上复用多路流，双方各自在 loopback 端口上互相访问，因此不要求本机的 IP 对该机器可达，切换 VPN 或网络时也不需要重新接入。对目标 sshd 的唯一要求是能免交互登录并执行命令，不依赖 `AllowTcpForwarding` 等端口转发设置。检查阶段会在目标机器上探测可用的 loopback 端口，找不到时计划会被阻止。接入完成后本机持续维持这条会话，断开后自动重连；两端每 15 s 互相探测，对端 30 s 内得不到本机应答时自行退出并释放端口。“高级网络设置”可指定该机器自己的选举地址；留空时使用自动值。安装计划会显示地址变更，加入投票成员前会检查同步情况。

安装使用计划所绑定的 SSH 连接。连接失效时不会改用后来修改的 SSH 配置发送私人入组包。安装结果不确定时，保留原计划并查询同一次操作；不要同时创建第二份安装。

已登记但尚未确认连接的完整节点，可从原接入记录选择“继续核对接入结果”。这会核对同一操作，不会重新上传程序或创建另一份安装。

新节点的 Agent 列表为空。接入完成后，可选择“登记这台机器的 Agent”，检测并登记目标机器已有工具。程序支持 macOS/Linux 的 arm64 和 amd64；目标机器还需要 Git 和安装检查列出的系统工具。

手动接入的独立 `steve-node` 升级后也能持有原生会话与执行回执，供协调节点核对和接续；它仍只是执行节点，不因此成为投票成员。节点协议比协调节点旧的 `steve-node` 在握手时即被拒绝，应升级并重启目标 `steve-node`，再检查原任务；见[节点协议版本](operations.md#节点协议版本)。

## 协调与交接

协调节点负责调度、协作记录和任务进展。界面显示“由某台机器协调”；执行任务的机器可以与协调节点不同。

“交接”只改变协调职责，原机器和目标机器都保持在线。交接不移动项目主目录，也不自动搬迁正在运行的原生进程。原机器重新连接后，App 会定位当前协调节点，并显示交接及后续任务记录。

| 规模 | 手动交接 | 自动容灾 |
|---|---|---|
| 1 个完整节点 | 无其他目标 | 不具备 |
| 2 个完整节点 | 两台在线并同步后可交接 | 不允许 |
| 至少 3 个完整节点 | 有可用目标且能形成多数派时可交接 | 默认关闭；至少 2 个节点获准自动接任后，才可开启 |

完整节点必须位于不同的物理故障域。同一机器上启动多个进程不能凑出容灾规模。新节点默认不允许自动接任。

离线不会自动缩小投票成员数。两个投票节点中有一个失联时，剩余节点无法单独完成新的权威写入或交接；三个投票节点中有两个失联也同样如此。

## 中断与恢复

协调节点失联时，满足自动容灾条件的机群可以选出新协调节点。手动交接与自动接管都会留下记录。健康执行节点上的原任务继续运行，新协调实例会核对原任务、执行和输入回执后重新接续。

执行节点本身失联时，系统会检查已保存的快照、实际副本、替代节点的能力与数据权限。未复制的文件修改和原生进程内存不能凭空恢复。不能确认原执行已停止或某项外部操作是否发生时，任务会向用户说明检查过程、问题与建议，等待针对具体恢复方案的决定。

用户授权恢复后，新执行使用隔离目录，并保留原任务和会话关系。旧执行不再具有提交新结果的资格。需要写回仍离线的项目主目录时，落地仍需等待目录恢复并重新合并。

已持久化的内容副本丢失后，当前协调节点会尝试在其他合规节点补齐副本。缺少可读副本、授权或可用机器时，会记录保护退化；不能把账本中的摘要当作实际文件已经可用。

用户主动暂停或取消任务会请求原生执行停止，并核对回执。对话中的“停止”按钮停止当前回合，也一并停止该任务派发出去、仍在运行的子任务（委派卡片显示“已取消”）；之后任务不会因子任务结束而自行继续，下一条消息的回合会先看到这些子任务留下的状态和结果。关闭 App 窗口、连接断开或协调实例退出本身都不是原执行停止的证据。

会话处于“正在恢复”或等待恢复决定时，“停止”针对的是原任务及其子任务，不只是关闭恢复提示，也不依赖当前选中的 Agent。只有原执行均确认结束后，原任务的恢复等待才会结束；原节点离线或停止结果不明时，会保留任务、待发指令和等待提示。恢复相关机器后，可再次点击“停止”核对。

若会话创建响应丢失、尚未获得原生会话标识，可在原任务的恢复问题中重新检查。查不到记录不代表原请求已取消；系统不会据此另开会话或重发输入。若不再继续，点击“停止”会按原创建指令请求取消：节点确认它未创建且不会再启动，或确认已创建的原进程已停止后，才完成取消。收到确认后再重新发起任务。

## 操作记录

原生 Agent 问题和平台恢复问题都直接回答当前等待，不新建一轮任务。可按建议选择、等待或补充文字；恢复授权只覆盖显示的那份方案。飞书来源的保留子任务需要在 App 中处理时，会出现标明原会话、父任务和项目的恢复会话。

同一机群内转移协调职责应使用“交接”。旧离线项目导出、导入命令不适用于共享账本，不能用它们绕过机群多数派或遗漏共享状态。
