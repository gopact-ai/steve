# 桌面与多机协作

Steve 的 macOS App 是本地工作台，后台服务保存项目、会话和任务。单机可以独立使用；其他机器可以提供执行能力，也可以成为保存协作账本的完整节点。

## 启动与数据

从 [Releases](https://github.com/gopact-ai/steve/releases) 下载 macOS App，或使用 `make desktop` 从源码构建。构建需要 macOS 13+、Go 1.27+、Git、Node.js/npm 和 Xcode Command Line Tools。可选的 upx 用于压缩随包分发的 Linux 节点程序。

App 与 `steve init` 共用本机安装。首次启动建立身份、私有状态目录和后台服务，无需飞书或其他机器。先登录本机 agent 工具，再在工作台登记。App 检查常见安装路径，不执行 shell 启动脚本。

macOS 状态保存在 `~/Library/Application Support/Steve/`。项目使用自己的工作区目录，建议放在 `~/steve` 等不参与云同步的位置。控制台及协作端口首次选取后保持稳定。

关闭窗口保留后台任务，重新打开连接原服务。替换 App 后若服务版本不同，会登记空闲后重启；设置页显示等待原因。页面加载失败时「重试」只重新打开工作台，不重新提交任务。

## 阅读与外观

设置支持系统、浅色和深色模式，以及界面、正文、标题和代码字体。自定义配色可以导入和导出。外观与草稿保存在当前客户端，不随集群同步；清理网站数据会清除它们。

文件查看器提供源码、Diff 和 HTML 预览。HTML 在隔离 iframe 中运行，不能访问工作台存储或调用原生文件选择器；SVG 不执行脚本。依赖其他本地文件或登录的产物可能需要独立运行。

## 接入机器

资源页的「通过 SSH 接入」从本机 SSH config 选择目标。检查后显示程序、目录、网络与成员变更，确认安装计划再执行。目标需要免交互 SSH 登录、Git 和检查列出的工具，支持 macOS/Linux 的 arm64、amd64。

| 节点类型 | 保存的内容 | 用途 |
| --- | --- | --- |
| 执行节点 | 本机执行状态、项目工作区、运行环境与产物 | 提供工具、算力或网络访问 |
| 完整节点 | 执行状态及协作账本副本 | 参与投票、交接协调职责 |

完整账本包含任务正文、问答和私人记忆，完整节点必须允许 `restricted` 或更高数据范围。共享账本不支持 `sealed` 项目；此类项目使用独立单机部署。

检测到已有安装时，界面展示路径和可读身份，不覆盖原安装或合并项目。安装结果不明时，从原接入记录继续核对，保留同一操作身份。新节点初始没有 agent，可在接入后检测和登记目标机器已有工具。

SSH 接入通过持续的 SSH 会话承载协作连接，断开后重连；不依赖 sshd 的 TCP 转发选项。手工执行节点的安装、归属和认证见[运维指南](operations.md#部署-node)。

## 协调与交接

协调节点负责调度与协作记录，实际执行可以发生在其他机器。「交接」改变协调职责，不移动项目主目录，也不搬迁运行中的进程。

| 完整节点规模 | 手动交接 | 自动容灾 |
| --- | --- | --- |
| 1 个 | 无其他目标 | 不具备 |
| 2 个 | 两台在线并同步后可交接 | 不允许 |
| 至少 3 个 | 可形成多数派且目标可用 | 默认关闭；至少 2 个节点获准自动接任后可开启 |

投票节点须位于不同物理故障域，同一台机器上的多个进程不增加容灾能力。节点离线不会减少投票成员数；两节点失去一个时，另一节点不能单独进行权威写入。

## 中断与恢复

协调节点更换后，新协调者核对原任务、执行与输入回执，再接回健康执行节点上的工作。执行节点本身离线时，恢复取决于可读快照、内容副本、目标能力和数据权限。未复制的改动与进程内存无法从账本重建。

恢复卡片说明原执行状态、阻塞和可用决定。不能确认原进程停止时保留隔离，不允许另一个执行占用相同写入目录或受限容量。授权替代执行后使用隔离目录；项目主目录仍离线时，结果需要等待落地。

「停止」会请求当前回合及仍运行的委派子任务结束；暂停、取消和恢复以任务列表中的状态为准。关闭窗口或网络断开不证明进程退出。回合结束也会清理属于该执行进程组的后台程序。

### 强制停止与放弃

普通停止无法确认时，原会话或执行详情提供「强制停止」，需要再次确认。它取消原任务及子任务，并向能够证明归属的原执行进程组发出终止请求；结果必须由退出证据确认。部分 Linux SSH 节点可经原连接持有者重启，影响该节点上的其他执行；界面会说明影响及不支持的情况。

强停耗尽后，owner 可显式「放弃这次执行」。放弃不可撤销，且不表示进程已停止：原进程可能仍在运行或写目录。系统记录取消与计量截止，并按持久记录处理归档和容量释放；处理未结束时仍显示等待。

只有确认风险并准备承担原进程继续运行的后果时才使用放弃。节点能恢复通信时，优先核对原停止结果。

## 更新与操作记录

经 SSH 接入桌面集群的节点可从资源页升级或重启。手工部署的执行节点需要在目标机器更新；协议不兼容时界面指明应升级的一端。升级和重启会中断目标上的执行，按原任务恢复机制核对。

机器详情显示最近操作；历史保留接入、交接、重启和恢复记录。判断成功时分别查看配置保存、机器连接和任务执行结果，安装回执不代替实际可用性。
