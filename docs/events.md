# 连接外部事件

Steve 可以把外部变化交给项目中的 agent 处理。Provider 负责连接外部服务并发布事件，订阅决定事件进入待处理列表、某个会话，还是另一个 Provider。

## 可用的 Provider

| Provider | 接收的内容 | 配置指南 |
| --- | --- | --- |
| 邮件 | Gmail、Outlook、Hotmail、iCloud Inbox 中的新邮件 | [邮件账号与同步](../providers/mail/README.md) |
| GitHub | PR 开启、提交变化、关闭、评审、检查结果及默认分支失败运行 | [仓库事件](../providers/github/README.md) |

Provider 是独立进程，需要单独安装、账号授权和运行。控制台中的连接登记保存授权，不启动 Provider，也不自动创建 agent 或订阅。

## 连接与授权

在「接入与事件」的连接页创建专用 Provider 连接，选择允许发布的事件类型。一次性返回的连接凭据保存在 Provider 的私有环境中。它与控制台 owner token 不同。

连接可以修改作用范围或旋转凭据，逻辑身份保持不变。凭据丢失时旋转原连接；重新创建来源会改变事件去重身份。撤销连接后不能靠重新登录恢复授权。

## 选择处理方式

| 订阅方式 | 结果 |
| --- | --- |
| Inbox | 留在待处理列表，由你决定后续动作 |
| Work | 交给已绑定项目的会话，按保存的指令处理 |
| Provider | 由指定的已登记 Provider 消费并回传结果 |

规则按事件类型或命名空间匹配，也可限定来源。Work 需要明确项目、会话和处理指令。外部正文是资料，不能代替你授予操作权限。

例如，新邮件可以使用指令：“概括内容，列出待办、截止时间和需要我回复的事项。”GitHub 检查失败可以使用：“读取该 PR 当前提交的失败日志，说明原因与建议。”需要 agent 修改仓库时，再把具体允许的动作写入指令，并配置执行机器的仓库访问。

保存规则后，新投递固定当时的规则版本。已有事件可在核对后显式重新处理；新规则版本可能产生新投递。停用订阅阻止后续处理，不撤回已发生的外部动作。

## 查看状态

消息总线显示等待投递、处理中、失败、结果不明和待处理数量。一个事件可以匹配多个订阅，因此事件数与投递数不是同一单位。

事件详情保存原始内容与当时的契约说明，投递详情显示目标、订阅版本和回执。事件已受理表示 Steve 保存了输入；Work 已受理表示工作进入执行入口；完成需要读取实际任务结果。

流动图呈现近期观察到的活动与当前等待数量，有短暂动画延迟。积压较多时合并显示并标明倍率；减少动态效果设置会使用静态队列。准确数量以同一快照的计数为准，动画不是吞吐量测量或完整日志。

## 失败与恢复

Provider 保存同步位置和待发布记录，发布重试沿用稳定事件键。Steve 的未知外部结果需要核对原回执；请求超时不代表动作未发生。

未匹配的事件、处理失败和未知结果进入待处理。先查看原任务或外部服务，再决定重试或对账。只有明确声明可安全重放、并且消费者持久去重的操作才能自动重试。

Provider 作者与客户端接入者参阅[事件与客户端协议](event-providers.md)。
