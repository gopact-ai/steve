# 项目、主目录、副本、工作树

- **项目**由 hub 声明：名字、怎么改（`inplace` 直接改主目录 / `isolated` 每步在工作树里改完再合并）、数据等级（public < internal < restricted < sealed）、可选的外部 remote、固定的技能。
- **主目录**：项目在其主机器上的目录本身；合并落回这里；同一时刻只有一个写者。
- **副本**：用户在别的机器上认领或克隆的同一项目目录。那台机器上的 agent 就在副本里干活。副本**不自动**落回主目录，靠 git 与主目录同步——你在副本里改完，要么提交并推到 remote，要么把这件事告诉用户。
- **工作树**：为一次计划步骤 / 委派 / 验证从某个快照检出的临时目录，用完即弃；结果经 publish 与 landing 进主目录。

一个会话绑定一个项目，不绑工作区：你在哪个工作区由你所在的机器决定——主机器就是主目录，有副本就是副本，都没有就不能在这台机器上接这个项目。

# 你现在在哪

看本轮指令里的"项目 / 目录"，或 `pwd`。规则：

- 只在当前工作区内写文件、建目录、删东西；外面的路径先问。
- 直接修改模式下，你的回合前后各拍一次快照，差异记成产物；这不是备份，别指望回滚。
- 隔离模式下的计划步骤：你在工作树里，只改这一步声明会碰的路径（`touches`），并行的步骤不能重叠；`inputs/<步骤>/` 下是要收敛的分支结果（merge 步骤才有）。

# 被告知"项目在别的机器"

Steve 会说清项目有工作区的机器和你所在的机器。三条路：让用户换一个在那台机器上的 Agent（`/use`）；请用户在你这台机器上给项目添加一个副本（项目页）；或 `/project use <id>` 换项目。不要在本机凭空造一个目录冒充。

# 数据等级

机器等级低于项目等级，项目的文件就不会放到那台机器上；`sealed` 的项目只在主机器上。委派时 `requires` 满足了但等级不够也会被拒，这是设计。

# 动词

- `/project`：看当前项目；`/project use <id>` 切换本会话的项目（旧会话归档，下一轮在新目录重开；已开的任务不跟着变）。
- `/grant <project> <who> <role>`：授予某人对项目的角色（none / read / write / admin）。
