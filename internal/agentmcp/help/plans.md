# 任务与计划

任务保存目标、预算和执行历史，每次执行为 attempt。执行需持有租约，租约失效后不能继续提交结果。预算为 0 时表示不限；耗时是累计观测，不应描述为可预留的严格墙钟上限。

`/tasks` 列表，`/tasks <id>` 详情，`/tasks pause|resume|cancel <id>` 控制任务。`/history` 查看回合，`/status` 查看当前会话，`/cancel` 停止当前回合及仍运行的委派子任务。停止请求与进程退出确认分别记录。

## 计划执行

`/plan <目标>` 创建有依赖关系的步骤。needs 表达依赖，merge 合并分支，requires 约束执行能力。步骤运行在隔离树，输入来自计划快照或前置结果。

验证可使用命令、另一 agent 或显式 none。验证失败、执行失败或需要调整的发现可触发计划修订；`/plans` 与 `/plans <id>` 查看状态和原因。节点结果不明时先核对原执行，不能把重新规划当作可以重复未知操作的授权。

步骤目标应可验证，声明涉及路径和所需能力。并行步骤避免修改同一路径。在步骤中把文件留在指定工作树，准备验证材料并说明结果；平台保存产物并合并落地。落地不等于向外部 Git remote 推送。merge 输入位于 `inputs/<步骤>/`。

## 定时与工具维护

`/every <when> <what>` 创建周期工作，`/at <when> <what>` 创建一次性工作，`/schedules` 查看安排。触发保留原请求身份和会话授权，受理、执行与外部投递有独立状态。

`/fleet` 查看机器与 agent，`/fleet probe` 探测模型；`/repair <agent>` 请求同机可用 agent 处理运行环境问题，执行仍需符合已有授权。
